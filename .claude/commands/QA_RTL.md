# כלל הכתיבה בעברית - שמירה על RTL

מטרת הכלל: מנוע רינדור קובע את כיוון הפסקה לפי **התו החזק הראשון** בה. שורה שנפתחת במילה
לועזית, ב-code span או בספרה מתהפכת ל-LTR ומשבשת את הפריסה. לכן:

**כל כותרת, סעיף, פסקה, פריט ברשימה ושורה בטבלה חייבים להיפתח במילה עברית.**

## דוגמאות

| שגוי | נכון |
|------|------|
| `RPC-style is simple but...` | `בגישת RPC-style הדברים פשוטים, אך...` |
| `## 8. פקודות שימושיות` | `## סעיף 8 - פקודות שימושיות` |
| `` `BaseMatcher` אינה ממשק ריק `` | `` המחלקה `BaseMatcher` אינה ממשק ריק `` |
| `**1. התזמור נשאר פונקציית מודול**` | `**ראשית, התזמור נשאר פונקציית מודול**` |
| `- POST /api/scan מחזיר...` | `- בקריאת POST /api/scan מוחזר...` |
| `409 מוחזר כאשר...` | `הקוד 409 מוחזר כאשר...` |

## כללים נוספים

- בטבלאות יש למקם **עמודה עברית ראשונה** (`פעולה`, `מקרה`, `כלי`, `אפשרות`), כך שכל שורה נפתחת
  בעברית. עדיף לשנות את סדר העמודות מאשר להשאיר שורות שנפתחות ב-`POST` או ב-`app/crud.py`.
- בלוקי קוד מגודרים **פטורים** - הם נרנדרים LTR ממילא.
- בחצים בתוך טקסט עברי עדיף `->` על פני `⇒` או `→`, שנוטים להתהפך.
- בציטוט מכוון של טקסט אנגלי (למשל שורה מתוך `README.md`) הכלל אינו חל - זהו חריג לגיטימי
  שיש להשאיר, ולא לתקן.
- הכלל חל גם על תשובות בעברית בצ'אט, לא רק על הקובץ.

## איתור ההפרות

יש להריץ את הגלאי, שמדלג על בלוקי קוד, שורות המשך, קווים מפרידים ושורות הפרדה של טבלאות:

```bash
python3 .claude/skills/project-workflow/scripts/check_rtl.py docs/QA.md
```

הפלט מציג מספר שורה וטקסט לכל הפרה, וקוד היציאה הוא 1 כשנמצאה לפחות אחת.

## מה לעשות

בהפעלה **ללא ארגומנטים**: יש להריץ את הגלאי על `docs/QA.md`, לתקן כל הפרה על ידי הוספת פתיח
עברי או שינוי סדר, להריץ שוב לאימות, ולדווח בטבלה מה תוקן ואיפה.

בהפעלה **עם ארגומנט** (נתיב קובץ): יש להחיל את התהליך על אותו קובץ בלבד.

חשוב: אין לשנות את **התוכן** של התשובות - רק את הניסוח שמבטיח את כיוון הכתיבה. אם תיקון דורש
שינוי משמעות, יש לשאול ולא לנחש.
